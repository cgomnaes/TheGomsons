PublicSchema.ckdb — CloudKit Public Database declarative schema for TheGomsons.

The .ckdb file must not contain // comments; cktool validate-schema and the server
parser can fail with obscure errors if comments are embedded in the schema text.

Authorize first: xcrun cktool save-token

Schema workflow (required — cktool cannot write Production):
1. Import into **Development** only:
     xcrun cktool import-schema --team-id <TEAM_ID> \
       --container-id iCloud.com.gomnaes.TheGomsons \
       --environment development --file CloudKit/PublicSchema.ckdb
   (`--environment production` fails with: endpoint not applicable in production.)
2. Promote to Production in CloudKit Console:
     https://icloud.developer.apple.com → container → Schema → **Deploy Schema Changes**
   Review the diff (new types like CD_FamilyGroupPhoto, inventory fields, grants) → Deploy.

This app’s entitlement pins Xcode + TestFlight / App Store to **Production**, so sync for
family devices only works after step 2. Development is just the staging schema.

If Xcode logs: "Cannot create or modify field '…' in record 'CD_*' in production schema",
Production is missing that field — finish Development import + Deploy Schema to Production.

GRANT WRITE TO "_icloud" allows any signed-in iCloud user to update existing records
(collaborative editing). After import, confirm indexes (___modTime, recordName, etc.)
in Console if mirroring logs still complain.

Recipe ingredients: the app persists `ingredientsJSON` (maps to CD_ingredientsJSON).
**Production cannot remove fields:** once CD_ingredients (BYTES) exists in Production,
it must stay in PublicSchema.ckdb forever (or import fails). Keep both CD_ingredients
and CD_ingredientsJSON on CD_Recipe. The app only reads/writes ingredientsJSON; legacy
CD_ingredients bytes are ignored unless old clients still use them.

FamilyPerson social fields: CD_hobbies, CD_partnerStatusRaw, CD_isDeceased, CD_deathDate,
CD_siblings, CD_siblingOf (plus contact fields CD_email, CD_mobile, CD_city,
CD_cityLatitude, CD_cityLongitude, CD_familyRelationLabel, CD_includeBirthdayOnCalendar)
must be present in Development and Production before mirroring those attributes.
Import/deploy PublicSchema.ckdb after shipping this model update if CloudKit logs
complain about missing fields.

Belongings (InventoryItem) extensions: CD_purchasePlace, CD_locationDetail, CD_productURL,
CD_insuranceNotes on CD_InventoryItem; new record types CD_InventoryItemLink and
CD_InventoryItemDocument (PDF/image attachments for receipts, manuals, guarantees).
Import/deploy PublicSchema.ckdb to Development and Production after this ship.

Family group album: CD_FamilyGroupPhoto (caption, sortOrder, addedAt, imageData) must
exist in Development and Production. Missing this type stalls Public mirroring when the
app exports group photos—import/deploy PublicSchema.ckdb after shipping FamilyGroupPhoto.

Recipes tied to places: CD_placeLabel, CD_notes, CD_sortOrder, CD_property on CD_Recipe.
Import/deploy PublicSchema.ckdb (Development → Deploy to Production) after shipping
the recipe box so family devices can sync place-linked recipes.

Property maintenance log: new record type CD_PropertyMaintenanceEntry (title, categoryRaw,
performedAt, nextDueAt, performedBy, costAmount, notes, photoData, property, sortOrder).
Import/deploy after shipping the maintenance log UI.

Subscriptions: CD_expiryDate (TIMESTAMP) and CD_includeInSummary (INT64/bool) on
CD_Subscription. Missing these fields in Production makes every subscription save fail
CloudKit export (“Cannot create or modify field… in production schema”) so other users
never see updates—import/deploy PublicSchema.ckdb (Development → Deploy to Production).

Holiday trip reviews: CD_reviewText plus CD_reviewPhoto1Data / CD_reviewPhoto2Data /
CD_reviewPhoto3Data (each BYTES + _ckAsset) on CD_HolidayTrip. Import/deploy after
shipping the past-trip review UI (up to three photos).

Property register URL: CD_propertyRegisterURL on CD_Property (Kartverket /
eiendomsregisteret links for Norwegian properties). Import/deploy after shipping.

Family nicknames: CD_preferredName on CD_FamilyPerson. Missing in Production blocks every
person export that includes the field.

Property rental block: CD_tenureRaw, CD_landlordOrOwnerName, CD_rentalCompanyName,
CD_rentalCompanyPhone, CD_rentalCompanyEmail, CD_depositAmount, CD_monthlyRent,
CD_leaseStartDate, CD_leaseEndDate, CD_rentalContractReference, CD_rentalContractNotes
on CD_Property. Missing CD_depositAmount alone is enough to fail property export.

Trip planning picks: RECORD TYPE CD_HolidayPlanItem (title, detail, categoryRaw, placeName,
mapsQuery, lat/long, sortOrder, sourceRaw, createdAt, trip). Missing type →
“Cannot create new type CD_HolidayPlanItem in production schema”.

Many-to-many join: Core Data uses record type CDMR with fields CD_entityNames,
CD_recordNames, and CD_relationships (semicolon-separated strings), not CD_entityName.
PublicSchema.ckdb includes those three (plus CD_entityName if already deployed — Production
cannot drop fields). Import to Development, then Deploy Schema to Production.

Holiday reviews: CD_reviewText (+ review photo BYTES/_ckAsset) on CD_HolidayTrip — must be
in Production before past-trip reviews sync.

Celebrations / party planner: CD_tripKindRaw, CD_celebrationSubject, CD_celebrationVenue,
CD_celebrationMenu, CD_linkedProperty on CD_HolidayTrip; CD_isAttending + CD_rsvpStatusRaw on
CD_HolidayTripParticipant; new RECORD TYPE CD_HolidayTripGuest. CD_sortOrder on CD_Property.
Missing any of these in Production → export partialFailure (error 2) when saving trips,
celebrations, property order, or subscriptions (CD_expiryDate / CD_includeInSummary).

If Xcode shows Partial Failure (2) with nested "Network Failure (4); Fetching asset failed"
on CD_FamilyPerson (same record UUIDs every retry): CloudKit cannot download photo assets
(CD_photoData_ckAsset). Export can still succeed. Fix: clear/re-upload those photos in the
app, or in CloudKit Console → Public → Records delete the broken asset fields on those
CD_FamilyPerson rows. Simulator asset CDN is flaky—confirm on a real device before assuming
permanent corruption.

  □ CD_preferredName (+ _ckAsset) on CD_FamilyPerson
  □ CD_depositAmount (+ rental fields above) on CD_Property
  □ CD_propertyRegisterURL on CD_Property (if not already deployed)
  □ CD_reviewText (+ review photo fields) on CD_HolidayTrip
  □ CD_tripKindRaw, celebration fields, CD_linkedProperty on CD_HolidayTrip
  □ CD_isAttending, CD_rsvpStatusRaw on CD_HolidayTripParticipant
  □ RECORD TYPE CD_HolidayTripGuest
  □ CD_sortOrder on CD_Property
  □ CD_expiryDate, CD_includeInSummary on CD_Subscription (if subscriptions fail export)
  □ RECORD TYPE CD_HolidayPlanItem
  □ CDMR — only if non-empty (Console blocks empty CDMR promote); otherwise deploy without it first
1. Import CloudKit/PublicSchema.ckdb → Development (cktool or Console).
2. If Deploy fails with “empty type CDMR”: Cancel → Development Schema → delete CDMR → Deploy again.
3. CloudKit Console → Schema → Deploy Schema Changes → Production.
4. Re-download Production schema and confirm preferredName / depositAmount / reviewText / HolidayPlanItem.
5. Force-quit app, relaunch; confirm “CloudKit export succeeded”. Fix CDMR later if still logged.
